# 背景
@260620\1.md は私が今日見た悪夢の内容です. 
これを 3d で再現してほしいです. 
# 要件
## 仕様技術
* C#, AWS, TypeScript, Node, Jest
* 要件に応じて必要な技術, フレームワークは追加で検討する
* 本質的に不要だと思われる技術は使わなくても良い
* AWS は Iaas で管理する

## 設計方針
* クリーンアーキテクチャを意識する
* SOLID 原則を意識する
* 長期的に見て保守・運用のしやすいアーキテクチャである

## 開発方針
* アジャイル開発 * テスト駆動開発で進める
* 開発の規模が大きくなる場合,  管理Issue を作成し, 対応する子Issueも作成して段階的にコーディングを進める
  * 管理Issueでは子Issueの管理も担う
  * 対応する子Issueについて実装が完了したら, PR を作成する
* 生成したプログラムについて, 認知負債を減らすために子Issueが完了したタイミングで実装内容を suumary ディレクトリに保存する

## アプリ仕様
* web 上で動作可能である
* ルーティングにより画面選択ができる
* 最初の選択画面で, 再現した悪夢を選択したら悪夢の 3d を再生できる
  * 悪夢の再生中は自分は操作できなくてよい
* 悪夢の再生が完了したら選択画面に戻る

## 開発手法
* 開発を進めるにあたって, 必要に応じて新しいアイデアを出し, 提案してかまいません
* AI で自律的に開発を進めるプロセスを新しく構築して構いません
  * その際, 新しくプロセスを開発した場合は process ディレクトリに開発したプロセスについての記載をしてください
* テスト手法については不備がないように必要に応じてメトリクスを用いてください

## その他
* 開発手法について新しくキャッシュを持っておいた方が望ましいと感じた場合, process ディレクトリに自律的に追加して構いません
* process ディレクトリが存在する場合, キャッシュを参照するために確認してから開発してください
* サブエージェントを使って並列的に実装などできる場合, して良いです
  * そのような AI Agent を使った新しい開発手法なども process ディレクトリ に追加してください
